Every file is transactional. Production correction is forward-fix first; never rewrite an already applied migration.

Package 13.2 creates one `FINANCIAL_ASSET` ledger account per financial account using `ASSET-<financial_account.account_number>` codes and adds append-only manual exchange rates. It does not seed CONTROL accounts, add ledger entries, create balances, post transactions, retrieve rates automatically, activate Accountant access, or change `public.current_account()`.

Package 13.3 creates the central ledger schema and implements only the `OPENING_BALANCE` subtype through atomic Owner/Admin approval and posting. It creates `CTRL-OPENING-<currency_code>` CONTROL accounts on demand for posted opening balances, stores transaction-date exchange-rate snapshots, and derives balances only from POSTED ledger entries.

Package 13.4 adds full reversal and controlled adjustment correction workflows only. Reversals copy posted ledger entries with debit/credit and reporting sides exchanged. Adjustments post exactly two same-currency lines using `CTRL-ADJUSTMENT-<currency_code>` CONTROL accounts. Package 13.4 does not add payment, expense, transfer, currency-exchange business, refund, Flutter, Edge Function, Accountant, document-finance, arbitrary journal-entry, partial-reversal or editable-balance workflows; it does not change `public.current_account()`.

Package 14.1 adds Client Payment intake and posting only. Approved payments post exactly two same-currency source lines: debit the receiving financial account asset ledger and credit `CTRL-CLIENT-PAYMENT-<currency_code>`. Client-created submissions start directly as submitted, have no ledger effect until different-Owner approval, and expose only approved/posted safe reads to the owning Client. Package 14.1 does not add payment requests, matching, allocation across Projects, uploads, document-link activation, notifications, Flutter, Edge Functions, Accountant access, refunds or editable balances.

Package 14.2 adds Payment Request records only. Requests use `PREQ-000001` global numbering, exact statuses `DRAFT`, `SENT`, `VIEWED`, `PARTIALLY_PAID`, `PAID`, `OVERDUE`, `CANCELLED`, Owner/Admin draft/update/send/cancel/list/detail/overdue refresh, and current-Client safe list plus explicit detail-view acknowledgement. Package 14.3 replaces the zero-match response placeholders with approved-match aggregation. Package 14.2 creates no financial events, financial transactions, ledger entries, uploads, document-link activation, notifications, Flutter or Edge Functions.

Package 14.3 adds Payment Matching as allocation/reporting only. Client Payment posting remains the only ledger/account effect; Payment Matching never creates financial events, financial transactions, ledger entries, exchange rates, account movements or Project receipt totals. Approved active matches allocate already approved and posted, economically active Client Payments to sent/later Payment Requests in the same Project, Client and currency. Request paid and remaining values stay derived response values, not stored columns.
